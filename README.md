# OurLittleArchive

둘이 함께한 것들과 앞으로 같이 할 것들을 모아두는 비공개 기록 사이트.

음악 · 방탈출 · 독서 · 보드게임 · 머더미스터리 · 공간, 여섯 가지 테마를 다룬다.

## 시작하기

```bash
cp .env.example .env     # 값을 채운다 (아래 참고)
npm install
npm run db:migrate       # SQLite 파일 생성 + 스키마 적용
npm run db:seed          # 두 사람 계정 생성
npm run dev
```

http://localhost:3000 에서 열린다.

### .env

| 변수 | 설명 |
| --- | --- |
| `DATABASE_URL` | 개발은 `file:./prisma/dev.db` 그대로 두면 된다 |
| `AUTH_SECRET` | 세션 쿠키 서명 키. `openssl rand -base64 32` 결과를 넣는다 |
| `SEED_USER_A_*` / `SEED_USER_B_*` | 두 사람의 slug / 표시 이름 / 비밀번호 |
| `KAKAO_REST_API_KEY` | 책 검색과 장소 검색에 쓴다 |
| `NEXT_PUBLIC_KAKAO_JS_KEY` | 지도 표시에 쓴다. REST 키와 **다른 키**다 |

이름이나 비밀번호를 바꾸면 `npm run db:seed` 를 다시 실행한다. upsert 라 기존 기록은 그대로 남는다.

## 구조

테마 여섯 개가 사실상 같은 모양이라 — **항목 + 했음/하고싶음 + 각자 평점 + 각자 감상평** —
`Entry` 하나로 모두 표현한다. 테마마다 다른 필드만 `metaJson` 에 넣는다.

| 파일 | 역할 |
| --- | --- |
| `lib/themes.ts` | **테마 정의의 단일 출처.** 허용값, 기능 플래그, 테마별 meta 의 Zod 스키마 |
| `lib/theme-fields.ts` | meta 를 폼에 어떻게 그릴지. 검증이 아니라 표시 담당 |
| `lib/entry-schema.ts` | 폼 입력을 검증해 저장 가능한 모양으로 바꾼다 |
| `lib/entries.ts` | 화면이 쓰는 조회 함수 |
| `app/actions/entries.ts` | 등록·수정·평점·감상평·베스트·사진 서버 액션 |
| `lib/storage.ts` | 사진 저장. 위치를 숨겨 두어 클라우드로 바꾸기 쉽게 했다 |
| `lib/music/itunes.ts` | iTunes 곡 검색. 키 없이 쓰고 결과를 캐시한다 |
| `lib/music/embeds.ts` | 붙여넣은 유튜브/Spotify 링크를 임베드 주소로 바꾼다 |
| `lib/books/kakao.ts` | 카카오 책 검색. 키가 없으면 안내를 띄운다 |
| `lib/places/kakao.ts` | 카카오 장소 검색(로컬 API) |
| `components/places/kakao-maps-loader.ts` | 지도 SDK 로더. 탭을 옮겨도 한 번만 받는다 |
| `lib/auth.ts` | 세션. 읽기는 누구나, 쓰기는 로그인 |

### 테마를 추가하려면

1. `lib/themes.ts` 의 `THEME_KEYS` 에 키를 넣고 `THEMES` 에 설정을 더한다
2. meta 가 필요하면 Zod 스키마와 `lib/theme-fields.ts` 의 필드 표를 더한다

목록·상세·등록 화면은 이 설정을 읽어 동작하므로 화면 코드는 고치지 않아도 된다.

### 데이터 모델

- `Entry` — 모든 테마의 항목. `status` 로 했음(DONE)/하고싶음(WISHLIST) 구분
- `Participation` — 누가 경험했는지. 방탈출은 보통 둘 다, 머더미스터리는 각자.
  `role` 에 그 사람이 맡은 캐릭터를 적는다
- `Rating` / `Review` — 사람마다 하나씩. 감상평은 스포일러 플래그로 가릴 수 있다
- `Favorite` — 각자의 베스트 (보드게임 베스트가 여기 해당)
- `DailyPick` — 날짜별 추천 (음악의 오늘의 곡, 독서 추천 코너)
- `Photo` — 항목에 붙는 사진

## 사진

사진 업로드는 저장소를 설정해야 쓸 수 있다. 설정이 없으면 운영에서는 버튼 자체를
숨긴다. 눌러봐야 실패하는 버튼을 두는 것보다 낫다. 개발에서는 로컬 디스크로 동작한다.

업로드된 사진은 `./uploads` 에 저장되고 `/api/photos/...` 로 서빙된다.
서버에서 `sharp` 를 거치므로:

- 아이폰 HEIC 가 JPEG 로 변환된다
- EXIF 회전이 실제 픽셀에 적용된다
- 긴 변이 2400px 로 줄어든다
- EXIF 가 제거되어 촬영 위치가 링크로 새어나가지 않는다

## 음악

곡 검색은 **iTunes Search API** 를 쓴다. 키도 계정도 필요 없다.

고를 때 알아둘 것:

- 한글로 검색해도 잘 찾는다. 다만 제목이 로마자로 올 때가 있어
  (밤편지 → Through the Night) 저장 전에 고칠 수 있게 해 두었다.
- `country=KR` 을 붙이면 결과가 항상 0건이라 그 파라미터는 보내지 않는다.
- 분당 20회 제한이 있어 검색창은 입력이 멈춘 뒤에 호출하고, 결과를 10분간 캐시한다.

듣기는 두 가지다:

- **30초 미리듣기** — iTunes 가 주는 것. 곡을 고르면 자동으로 붙는다.
- **전곡 재생** — 곡 상세의 `고치기` 에서 유튜브 링크를 적으면 임베드로 재생된다.
  유튜브와 Spotify 임베드는 API 키가 필요 없다.

### 다른 음원 서비스를 안 쓴 이유

- **멜론 · 지니 · 벅스** — 공개 API 가 없다.
- **Deezer** — 키는 필요 없지만 한국 곡 검색이 거의 안 된다.
  "아이유 밤편지" 를 치면 엉뚱한 피아노 커버가 나온다.
- **MusicBrainz** — 한글 제목을 제대로 주지만 K-pop 검색 정확도가 낮고 초당 1회 제한이라
  검색창에 쓰기 어렵다.
- **Spotify** — 2024-11-27 정책 변경으로 신규 앱은 미리듣기 주소를 받을 수 없다.
  링크를 적어두면 임베드 재생은 된다.
- **YouTube Data API** — 한글 제목과 전곡 재생을 모두 주지만 Google Cloud 키가 필요하고
  검색이 하루 100회로 제한된다. 썸네일도 정사각 앨범아트가 아니라 16:9 영상 캡처다.
  나중에 한글 제목을 자동으로 채우고 싶으면 이걸 더하면 된다.

## 독서

책 검색은 **카카오 책 검색 API** 를 쓴다. 국내 도서는 사실상 유일한 선택지다.
알라딘 OpenAPI 는 2026-10 종료, 네이버 검색 API 는 신규 신청이 막혔고,
멜론처럼 다른 국내 서비스도 공개 API 가 없다.

### 키 발급 (책·공간 공용)

1. [developers.kakao.com](https://developers.kakao.com) 에서 애플리케이션 추가 (심사 없이 바로 된다)
2. [앱 키] 메뉴의 **REST API 키** 복사
3. `.env` 의 `KAKAO_REST_API_KEY` 에 붙여넣기
4. 개발 서버 재시작

플랫폼 등록, 카카오 로그인 활성화, 비즈앱 전환, 클라이언트 시크릿 모두 필요 없다.
쿼터는 책 검색 하루 30,000건(검색 API 전체 50,000건)이라 신경 쓸 일이 없다.

키가 없어도 사이트는 정상 동작한다. 검색창에 두 글자 이상 넣으면 발급 방법이 뜨고,
`직접 입력` 으로 책을 손수 등록할 수 있다.

### 표지 주소

카카오가 주는 `thumbnail` 은 120x174 로 작다. 주소 안의 크기(`R120x174`)를 키우면
더 큰 이미지가 올 것 같지만 **403 이 난다**. 그 주소는 크기가 고정되어 있다.

대신 `thumbnail` 의 `fname` 쿼리에 원본 이미지 주소가 들어 있고, 458x664 에서
800x1136 정도로 표지에 충분하다. 그래서 `fname` 을 꺼내 https 로 올려서 쓴다.

### 화면

- **추천 코너** — 음악의 "오늘의 곡" 과 같은 `DailyPick` 을 쓴다
- **읽은 책** — 두 사람의 평점과 감상평을 카드 하나에 나란히 보여준다.
  상세로 들어가지 않아도 목록에서 바로 비교된다
- **읽고 싶은 책** — 아직 감상평이 있을 수 없어 공통 카드를 쓴다

감상평의 스포일러 표시는 목록과 상세 양쪽에서 가려진다. 한쪽이 먼저 읽는 일이 많아서다.
ISBN 으로 중복을 막으므로, "읽고 싶은 책" 에 담아둔 책을 다 읽고 다시 등록해도
기록이 한 줄로 이어지고 거기 달린 평점과 감상평이 그대로 남는다.

## 공간

세 갈래로 본다: **데이트 갔던 곳 / 여행지 / 가보고 싶은 곳**.
DB 에는 `status`(DONE/WISHLIST)와 `subCategory`(DATE/TRAVEL) 두 칸으로 나뉘지만,
쓰는 사람 머릿속에서는 하나의 선택이라 화면에서는 세 가지 중 하나만 고르면 된다.
변환은 `app/actions/places.ts` 에서 한 번만 한다.

장소 검색은 **카카오 로컬 API**, 지도는 **카카오맵 JavaScript SDK** 다.
좌표가 함께 저장되어 탭마다 지도에 핀이 찍힌다.

### 설정 (책 검색과 다르다)

장소·지도는 책 검색보다 조건이 하나 더 있다.

1. **카카오맵 켜기** — [내 애플리케이션](https://developers.kakao.com/console/app) 에서 앱을 열고
   **[카카오맵] > [사용 설정]** 의 상태를 **ON** 으로 바꾼다.
   켜지 않으면 장소 검색이 403 과 함께
   `disabled OPEN_MAP_AND_LOCAL service` 를 돌려준다.
2. **JavaScript 키** — 지도 SDK 는 REST 키가 아니라 **JavaScript 키**를 쓴다.
   `.env` 의 `NEXT_PUBLIC_KAKAO_JS_KEY` 에 넣는다.
3. **플랫폼 등록** — 콘솔의 **[플랫폼] > [Web]** 에 `http://localhost:3000` 을 등록한다.
   등록하지 않으면 지도가 뜨지 않는다.

무료 쿼터는 **개발자 계정에서 처음 카카오맵을 켠 앱에만** 주어진다.
2026-07-21 에 카카오맵 API 사용 방식과 무료 쿼터 제공 방식이 바뀌었으니,
현재 수치는 콘솔의 [통계] > [쿼터] 에서 확인한다.

### 설정 확인

```bash
npm run check:kakao
```

책 검색 / 장소 검색 / 지도 SDK 를 한 번에 확인하고, 막힌 항목마다 어디를 눌러야 하는지 알려준다.
셋은 요구 조건이 조금씩 달라서 하나가 되는데 다른 하나가 안 되는 일이 흔하다.

설정이 안 되어 있어도 화면은 깨지지 않는다. 검색창과 지도 자리에 각각 무엇을 해야 하는지
안내가 뜨고, `직접 입력` 으로 장소를 손수 등록할 수 있다(좌표가 없으면 지도에만 안 찍힌다).

## 보드게임

**각자의 베스트**가 주인공이다. `Favorite`(사용자 × 테마 × 순위)로 관리하고
두 사람 목록을 나란히 보여준다. 순위는 본인만 ↑↓ 로 바꿀 수 있다.

`Favorite` 에 `(userId, theme, rank)` 고유 제약이 걸려 있어 두 줄을 그냥 맞바꾸면 충돌한다.
그래서 한쪽을 잠깐 음수 rank 로 빼두고 세 단계로 교환한다.

베스트에 넣고 빼는 건 게임 상세의 `내 베스트에 넣기` 에서 한다.

## 머더미스터리

**각자 해본 기록**이 주인공이다. 한쪽만 해본 작품이 많아서 한 목록에 섞으면
누가 뭘 했는지 묻히므로, 사람별로 칸을 나누고 둘이 같이 한 작품에는 `같이` 표시를 단다.

같은 작품이라도 맡은 캐릭터는 사람마다 다르다. 그래서 역할은 `Entry.metaJson` 이 아니라
**`Participation.role`** 에 둔다. 상세 화면의 `누가 해봤는지` 에서 각자 적는다.

감상평은 이 테마에서 스포일러 표시가 기본으로 켜진다.

### 커버 이미지

보드게임·머더미스터리·방탈출은 커버를 주는 공개 API 가 없다.

- **보드라이프** — 공개 API 없음
- **BoardGameGeek** — 등록과 토큰이 필요하고 비상업 승인에 일주일 이상 걸린다.
  인증 없이 부르면 401 이다
- **카카오 이미지 검색** — 이미 쓰는 키로 바로 된다. 이쪽을 쓴다

등록 화면의 `이미지 찾기` 를 누르면 제목으로 검색해 고를 수 있다.

검색 결과를 그대로 쓰지는 않는다. 상당수가 네이버 블로그 이미지인데 다른 도메인에서
부르면 403 이라 화면에 깨진 이미지만 남는다. 그래서 서버에서 브라우저와 같은 조건
(Referer 포함)으로 한 번 불러보고, 실제로 열리는 것만 보여준다.
Referer 없이 확인하면 블로그 이미지가 통과해버려서 걸러지지 않는다.

## 홈

읽히는 순서를 **오늘 → 최근 → 앞으로 → 테마** 로 잡았다.
이 사이트는 함께한 것과 앞으로 할 것을 같이 모아두는 곳이라,
지나간 기록만 쌓이지 않도록 앞으로 할 것들도 첫 화면에 둔다.

- **오늘** — 음악의 오늘의 곡과 독서의 추천 책. 같은 `DailyPick` 을 쓴다
- **최근 기록** — 테마를 가로질러 최근에 한 것 (DONE)
- **앞으로 할 것들** — 테마를 가로질러 하고 싶은 것 (WISHLIST)
- **테마** — 테마별 개수와 바로가기

최근 기록을 DONE 으로 한정한 이유는, 나누지 않으면 같은 항목이 한 화면에 두 번 나오기 때문이다.

## 공개 범위

링크를 아는 사람은 볼 수 있고, 기록을 남기려면 로그인해야 한다.
검색엔진에는 걸리지 않도록 `robots.txt` 와 메타태그로 막아두었다.

## 배포

Vercel + Neon(Postgres) + Cloudflare R2(사진) 조합을 쓴다. 셋 다 무료 범위로 돌아간다.

| | 고른 것 | 무료 범위 |
| --- | --- | --- |
| 호스팅 | Vercel | 대역폭 100GB/월. Hobby 는 **비상업용만** 허용된다 |
| DB | Neon Postgres | 프로젝트당 0.5GB, 컴퓨트 100 CU-시간/월 |
| 사진 | Cloudflare R2 | 10GB, **이그레스 무료** |

사진은 대역폭을 가장 많이 먹는 부분이라 이그레스가 무료인 R2 를 골랐다.
R2 는 S3 호환이라 나중에 다른 곳으로 옮겨도 코드는 그대로다.

### 1. Neon (DB)

[neon.com](https://neon.com) 에서 프로젝트를 만들고 **pooled 연결 문자열**을 복사한다.
host 에 `-pooler` 가 붙은 쪽이다. 서버리스는 연결이 금방 쌓여서 pooled 를 써야 한다.

개발도 같은 Postgres 를 쓴다. 브랜치를 하나 더 만들어 개발용으로 쓰면 된다.
SQLite 로 개발하고 Postgres 로 배포하면 마이그레이션 기록이 갈라지고,
로컬에서는 통과하는데 운영에서 깨지는 차이가 생긴다.

```bash
# .env 의 DATABASE_URL 을 채운 뒤
npm run db:deploy        # 마이그레이션 적용
npm run db:seed          # 두 사람 계정 생성
```

무료 플랜은 5분 쉬면 컴퓨트가 자동으로 멈춘다(해제 불가).
한참 만에 들어가면 첫 요청이 조금 느린데, 두 사람이 쓰는 사이트에는 문제되지 않는다.

### 2. Cloudflare R2 (사진)

버킷을 만들고 **R2 API 토큰**을 발급해 `.env` 의 `S3_*` 를 채운다.

- `S3_ENDPOINT` — `https://<계정ID>.r2.cloudflarestorage.com`
- `S3_REGION` — `auto` (R2 는 리전 개념이 없다)

버킷을 공개하거나 도메인을 연결했다면 `PHOTO_PUBLIC_BASE_URL` 에 그 주소를 넣는다.
채우면 이미지 요청이 서버 함수를 아예 거치지 않는다.

> 운영에서 `S3_*` 가 비어 있으면 업로드가 거부된다.
> Vercel 은 파일시스템이 휘발성이라, 막아두지 않으면 사진이 조용히 사라진다.

### 3. Vercel

저장소를 연결하고 환경변수를 넣는다.

| 변수 | 비고 |
| --- | --- |
| `DATABASE_URL` | Neon pooled 문자열 |
| `AUTH_SECRET` | `openssl rand -base64 32` |
| `KAKAO_REST_API_KEY` | 책·장소 검색 |
| `NEXT_PUBLIC_KAKAO_JS_KEY` | 지도. **빌드 전에** 넣어야 한다 (아래 참고) |
| `S3_*` | R2 접속 정보 |
| `PHOTO_PUBLIC_BASE_URL` | 공개 주소를 쓸 때만 |

**환경변수를 먼저 넣고 배포한다.** 특히 `DATABASE_URL` 이 없으면 빌드가 아니라
앱이 뜬 뒤에 모든 화면이 죽는다. Vercel 은 Settings > Environment Variables 에서 넣는다.

`SEED_USER_*` 는 운영에 넣지 않아도 된다. 계정은 로컬에서 운영 DB 를 향해
`npm run db:seed` 를 한 번 돌리면 만들어진다.

**`NEXT_PUBLIC_` 는 빌드 시점에 번들에 박힌다.** 나중에 값을 바꾸면
재배포해야 반영된다. 지도 키를 나중에 넣었다면 다시 배포한다.

### 4. 배포 후

- 카카오 콘솔의 **[플랫폼] > [Web]** 에 운영 도메인을 추가한다.
  `http://localhost:3000` 은 지우지 말고 같이 둔다.
- `npm run check:kakao` 로 세 연동이 살아 있는지 확인한다.

### 기존 데이터 옮기기

개발하면서 SQLite 에 쌓인 기록이 있으면 옮길 수 있다.

```bash
npm run db:import-sqlite              # prisma/dev.db 에서 읽는다
```

id 를 그대로 쓰고 이미 있으면 건너뛰므로 여러 번 돌려도 안전하다.
사진 레코드는 옮기지만 **파일은 따로** `./uploads` 에서 버킷의 같은 키로 올려야 한다.
